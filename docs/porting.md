# Перенос на C++

Редактор переносится с PascalABC.NET на C++. Старая реализация, версия 0.6.0,
лежит в `pascal/` и не правится: это эталон. Перенос сверяется с ним не по
описанию, а по живой программе — один и тот же сценарий прогоняется на обеих,
снимки окна сравниваются попиксельно.

## Что где

| Путь | Назначение |
| --- | --- |
| `pascal/` | оригинал на PascalABC.NET, эталон |
| `CMakeLists.txt`, `CMakePresets.json` | сборка переноса |
| `src/` | перенос; пока только проверка инструментов |
| `tests/` | тесты GoogleTest и запуск программы без экрана |
| `Resources/`, `Картинки/`, `Config.txt` | данные, общие для обеих версий |
| `tools/setup-env.sh` | установка всех инструментов |
| `tools/gui.sh` | запуск, управление и снимки окон оригинала и переноса |
| `tools/lint.sh` | clang-format, clang-tidy, cppcheck |
| `tools/pabcnet/` | заплатка компилятора PascalABC.NET для Mono |

## Установка

```bash
tools/setup-env.sh
```

Рассчитано на Ubuntu 24.04. Первый запуск занимает несколько минут, повторный
ничего не пересобирает. Ставится:

- **C++:** GCC 13, Clang 18, CMake, Ninja, ccache; gdb, lldb, valgrind;
  clang-tidy, clang-format, cppcheck, shellcheck.
- **Библиотеки:** SDL2, SDL2_ttf, SDL2_image; GTK3 и zenity для диалогов
  открытия и сохранения; GoogleTest.
- **Шрифты:** Liberation Sans — метрическая копия Arial, которым GraphABC
  пишет весь интерфейс (`Arial`, 10 пунктов).
- **Эталон:** Mono 6.8 с WinForms, .NET SDK 10 и компилятор PascalABC.NET,
  собранный из исходников (закреплён на коммите `643514c`).
- **Окна без экрана:** Xvfb, xdotool, ImageMagick.
- **Корпус игры:** клон [Andors-Love](https://github.com/dpsmpx/Andors-Love)
  с 50 картами и 107 тайлами.

Пути записываются в `~/.local/share/tjtm-tools/env.sh`. В облачной сессии
Claude Code всё это делает SessionStart-хук `.claude/hooks/session-start.sh`.

## Сборка и тесты

```bash
cmake --preset debug && cmake --build --preset debug && ctest --preset debug
```

| Пресет | Что даёт |
| --- | --- |
| `debug` | отладочная сборка GCC |
| `release` | оптимизированная с отладочными символами |
| `asan` | AddressSanitizer и UndefinedBehaviorSanitizer, утечки ловятся |
| `clang` | Clang, предупреждения считаются ошибками |
| `tidy` | Clang с clang-tidy на каждом файле при сборке |

Каталоги сборки — `build/<пресет>`. Программа без экрана:

```bash
SDL_VIDEODRIVER=offscreen SDL_FRAMEBUFFER_ACCELERATION=0 \
    build/debug/tjtm --frames 3 --screenshot shot.png
```

`SDL_FRAMEBUFFER_ACCELERATION=0` оставляет кадровый буфер программным. Иначе
SDL поднимает EGL и Mesa, и их собственные утечки LeakSanitizer приписывает
программе.

Проверка кода: `tools/lint.sh` — C++ и скрипты (с `--fix` правит оформление).

Отладка: `gdb build/debug/tjtm`, `valgrind build/debug/tjtm --frames 2`,
`compile_commands.json` для clangd лежит в каталоге сборки.

## Эталон

```bash
tools/gui.sh ref build            # собрать pascal/TJTM.pas под Mono
tools/gui.sh ref start            # запустить в своём Xvfb
tools/gui.sh ref key Escape       # из меню в редактор
tools/gui.sh ref drag 100 100 400 300   # мазок карандашом
tools/gui.sh ref click 700 160 3  # правая кнопка по палитре
tools/gui.sh ref shot ref.png     # снимок окна 780x560
tools/gui.sh ref stop
```

То же самое с `port` вместо `ref` управляет переносом. У каждой цели свой
виртуальный экран (`:99` и `:98`), поэтому их можно держать открытыми
одновременно. Сравнение:

```bash
tools/gui.sh compare ref.png port.png diff.png   # число несовпавших пикселей
```

Координаты — внутри окна, как в коде: холст `0..599`, панель `600..779`.

Оригинал собирается в `build/ref` вместе с копиями `Config.txt`, `Resources/`
и `Картинки/`: он пишет в `Config.txt` при работе, и файлы репозитория трогать
не должен. Каждая сборка возвращает его настройки к исходным.

### Чем эталон под Mono отличается от Windows

- **Текст.** Mono рисует через libgdiplus и cairo, Windows — через GDI+, и
  сглаживание букв у них разное. Arial подменяется Liberation Sans с теми же
  метриками. Поэтому подписи сравниваются по месту и ширине, а не попиксельно.
  Холст, палитра, обзор и полосы цвета рисуются без сглаживания, и там
  расхождений быть не должно.
- **Диалоги файлов.** У Mono свои окна открытия и сохранения, не системные.
- **Заплатка компилятора.** Компилятор PascalABC.NET падает в Mono 6.8 на
  `Type.GetConstructors()` для массива обобщённого параметра (`T[]`).
  `tools/pabcnet/mono68-generic-array-ctors.patch` пропускает этот запрос:
  такие массивы создаются инструкцией `newarr`, конструкторы им не нужны.
  Mono новее 6.8 в контейнер не поставить — сайты Mono закрыты сетью.

Исходники библиотек, на которых стоит оригинал, лежат в
`$PABCNET_DIR/bin/Lib`: `GraphABC.pas` (рисование, шрифт, `DrawTextCentered`,
`FillRoundRect`) и `PABCSystem.pas` (`Round`, `Random`, `StrToInt`). Поведение
переносится по ним, а не по памяти.

## Корпус Andors-Love

`$ANDORS_LOVE_DIR/data/maps/*.map` — 50 карт игры. Разбор и запись оригинала
дают на них файл байт в байт, и перенос обязан делать то же. Формат описан в
`pascal/TJTMMap.pas` и `src/world.cpp` игры, проверка — в `tools/check_maps.py`
игры (в README редактора она ещё названа `gen_maps.py`).

`$ANDORS_LOVE_DIR/data/tiles/*.png` — набор тайлов: 17 основных слотов,
жители `npc_*`, враги `mob_*`. Имена основных слотов — договор с
`src/gfx/tiles.cpp` игры.

Тесты, которым нужен корпус, читают `ANDORS_LOVE_DIR` и без него
пропускаются, а не падают.

## Поведение, которое легко потерять при переносе

Найдено при чтении оригинала и исходников PascalABC.NET.

- **Округление.** `Round` в PascalABC.NET — это `Convert.ToInt32`, то есть
  банковское: половина к чётному. В C++ это `std::nearbyint` при режиме по
  умолчанию, а не `std::lround`. На нём держатся `HSVtoRGB`, `BlendOver`,
  пересчёт полос цвета и `ZoomAt`.
- **Целая арифметика.** `div` и `mod` отсекают к нулю, как в C++. Там, где
  нужно вниз, оригинал сам зовёт `FloorDiv` или `Floor`.
- **Случайные числа.** `Random(a, b)` — включительно с обеих сторон,
  `Random(n)` — от 0 до n−1.
- **`StrToInt`.** Пробелы по краям допускаются, знак тоже, всё прочее —
  исключение; конфиг тогда берёт значение по умолчанию.
- **Строки.** Индексы 1-based (`s[i]`, `Copy`, `Pos`) перемешаны с 0-based
  методами .NET (`Substring`, `IndexOf`). Длина считается в единицах UTF-16:
  в C++ над UTF-8 это надо учитывать там, где строки не ASCII.
- **Массивы `[x, y]`.** `Tile[x, y]`, `MapGrid[x, y]`: первый индекс —
  столбец, второй — строка. Циклы идут строкой снаружи; этот порядок стоит
  сохранить, тогда промежуточные состояния легко сверять с оригиналом.
- **Цвет.** `SameColor` сравнивает `ToArgb`; штатное `=` для `Color` в .NET
  различает именованные цвета, поэтому оригинал его избегает.
- **Config.txt.** Пишется `File.WriteAllLines` с `Encoding.UTF8`: метка BOM в
  начале и перевод строки системы (на Windows CRLF). Читается UTF-8, а если не
  распознано ни одного ключа — повторно как CP1251.
- **Карты.** UTF-8 без BOM, перевод строки LF; при чтении снимаются CR и BOM.
  Неизвестный символ сетки — стена; строка не той длины дополняется стеной с
  предупреждением.
- **Ввод.** Обработчики мыши оригинала живут в потоке окна, поэтому клик
  снимается в начале кадра (`BeginFrameInput`) и достаётся ровно одной кнопке.
  В SDL события и так приходят в основной поток, но правило «один щелчок —
  одна кнопка» и «клик, пришедший посреди кадра, не теряется» надо сохранить.
- **Модальность.** Экраны — вложенные циклы (`ShowMainMenu` →
  `ShowSettingsScreen` → `AskText`), инструменты — циклы, пока кнопка нажата.
  Такую структуру можно перенести как есть, если каждый цикл сам разбирает
  очередь событий SDL.
- **Поле ввода.** Строки объектов карты правятся настоящим `TextBox`:
  выделение, каретка, `Ctrl+C`/`Ctrl+V`, раскладки. В SDL это свой виджет
  поверх `SDL_StartTextInput` и буфера обмена SDL.
- **PNG.** Читается всё, что открывает GDI+ (`Image.FromStream`, затем
  32bppARGB), пишется 32bppARGB. Предел тайла — 512×512.
- **Неиспользуемые ресурсы.** `Resources/Fill.png`, `Vd.png`, `X.png`,
  `_Pen.png`, `sFill.png`, `sPen.png`, `sVd.png` остались от версии 2024 года,
  код их не читает.
